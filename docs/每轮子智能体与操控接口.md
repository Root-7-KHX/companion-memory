# 每轮子智能体（操控中心）与操控动作接口

> 2026-11-13 新增。对应代码：`lib/ops-agent.js`、`lib/performance.js`（`ops` 字段）、`client.js`（性能模式页）、`index.js`（挂载）。
> 一句话：**每轮对话结束，插件自己再调一次模型，把这一轮拆给「情绪 / 语言习惯 / 记忆 / 操控」几个块分别处理**；操控块产出的动作放进一条总线，以后皮套之类的消费者来取。

---

## 1. 它解决什么问题

以前的记忆写入靠主模型自觉调用 `companion_memory` 的 `turn_end`；模型偷懒时只有一层「被动兜底」（`tracking.js` 的 passiveTurnEnd）。现在多了一层**每轮必跑、可分配**的分析器：

| 块 | 产出 | 落到哪里 |
|---|---|---|
| `emotion` 情绪 | 这一轮的情绪变化（只认已存在的情绪种类） | 情绪表（面板「情绪」页可见） |
| `style` 语言习惯 | 2~4 条「该怎么说话」（句式、口头禅、长度、语气） | `<会话数据目录>/ops.json`，并注入下一轮动态上下文「说话习惯」 |
| `memory` 记忆 | 1~2 条值得长期记的原文（人设、约定、剧情节点、固定偏好） | 活跃记忆，标签带「子智能体」 |
| `control` 操控 | 可被外部消费的动作（表情/动作/视线/参数/说话） | 动作总线 `ops.json → control.items`，等外部程序来取 |

失败的块不影响其它块；整体失败只写日志，不影响聊天。

## 2. 面板上怎么用

侧边栏「伴侣记忆」→「性能模式」→ 最下面的 **每轮子智能体（操控中心）**：

- **每轮都调用**：总开关。关掉完全不跑。
- **一次调用 / 分块调用**：一次调用 = 所有块合成一次模型请求（省）；分块 = 每块一次请求（结果更干净，4 块就是 4 次）。
- **分配到的块**：按对话勾选。默认开「情绪 / 语言习惯 / 记忆」，**「操控」默认关**（等皮套接上再开）。
- **立即分析本轮**：手动跑一次，用来验证/补记。
- 下方会显示上一次运行的时间、耗时、各块写了几条。

设置每个对话一份，存在 `<数据根>/performance.json` 的 `sessions.<会话id>.ops` 里；默认值（`defaults.ops`）：

```json
{
  "enabled": true,
  "mode": "single",
  "window": 12,
  "model": { "provider": "", "model": "" },
  "blocks": {
    "emotion": { "enabled": true, "hint": "" },
    "style":   { "enabled": true, "hint": "" },
    "memory":  { "enabled": true, "hint": "" },
    "control": { "enabled": false, "hint": "" }
  }
}
```

- `window`：送进子智能体的最近消息条数（4~40，默认 12）。
- `model`：留空 = **跟随当前对话的模型**（不额外买模型）；填 `{"provider":"deepseek-account","model":"deepseek-flash"}` 这类值就固定用它。
- 每块的 `hint`：给这一块的额外要求（例如「语言习惯只关注句长和口头禅」），会拼进提示词。

### 2.1 情绪波动（会不会当场变脸）

用户反馈「以前的 AI 情绪太稳定、不会瞬间变换情绪」。所以情绪块除了写情绪表，还带三件事：

1. **触发判断**：每轮先判断有没有情绪触发事件（被冒犯/被骂、被冷落/被敷衍、约定被放鸽子、被夸/被撩、被关心、被吓到、对方难过、对方越界…）。
2. **允许瞬间突变**：真有触发就允许从 0 直接跳到 60~100（`spike:true + trigger`），不需要平滑过渡；没触发只小幅调整或回落。
3. **情绪惯性（不许一秒冷静）**：突变的情绪会被记成一条「还在气头上」，之后每轮按档位回落；如果主模型下一轮 `turn_end` 想直接冷静下来，回合结束时会把它抬回本轮下限。同时把「还在气头上」写进下一轮动态上下文的行为指令（例如「可以变冷/顶回去，别急着讲道理或道歉」）。

面板上「情绪波动」四档：

| 档位 | 单次最大跳变 | 每轮回落 | 行为 |
|---|---|---|---|
| 稳定 | ±25 | 6 | 不主动突变，但保留小变化 |
| 正常（默认） | 85 | 12 | 有明显触发就当场变脸 |
| 敏感 | 100 | 18 | 更容易被带情绪，小刺也记一会儿 |
| 一点就炸 | 100 | 10 | 生气会持续好几轮，得哄 |

对应配置（`performance.json` 的 `ops.emotionTuning`）：

```json
{ "volatility": "normal", "decayPerTurn": null, "inject": true }
```

- `volatility`：上面四档。
- `decayPerTurn`：`null` = 用档位自带的回落速度；填 0~30 覆盖它（越小越记仇）。
- `inject`：是否把「还在气头上」写进下一轮的行为指令（关掉就只改情绪表，不说话）。

> QQ 路由会话：情绪照常写、惯性照常生效（下一轮从状态里读得到），但和 dynamic-context 一样不做 runtime-context 注入，避免宿主把快照当新消息投递。

### 2.2 跨对话共享的「整体情绪」（换个用户来聊，她还在气头上）

用户要求：在任意一个对话里被惹到，**换个人来跟她说话，她也还是不冷静**。所以突变不只写进当前对话：

- 突变同时记进**整体情绪**文件 `<数据根>/ops-global.json`（不按对话隔离）。
- 每轮（任意对话的任意一轮结束）整体情绪按各自记录的速度回落一轮。
- 每个对话下一轮开始时，会话内的情绪表会被抬到整体情绪的下限 —— 面板「情绪」页、桌宠表情、`turn_end` 回执看到的都是同一个心情。
- 网页对话：整体情绪写进动态上下文（`systemPrompt.context`）。
- **QQ 对话**：不走 runtime-context（防重复回复），改由 `companion_memory` 的 **turn_end 回执**携带（turn_end 在回复前调用，AI 写回复时就看得到）。
- 面板开关「情绪跨对话共享」可关（`ops.sharedMood`，默认开）。关掉后每个对话各算各的、互不传染。

## 3. 数据落盘

| 路径 | 内容 |
|---|---|
| `<数据根>/performance.json` | 每个对话的 `ops` 配置 |
| `<会话数据目录>/ops.json` | `style.lines`（语言习惯）、`control.seq/items`（动作总线）、`lastRun`（上次运行结果） |
| `<数据根>/ops.log` | 运行日志（单条：session / mode / blocks / 耗时 / 错误），超过 512KB 自动截断 |
| `<数据根>/debug-events.log` | 其它模块共用的调试日志（本模块不用） |

## 4. 操控动作总线（给以后的皮套等用）

### 4.1 取动作（轮询）

```
GET /companion/ops/control/pending?session=<会话id>&after=<上次拿到的 seq>
→ { ok: true, value: { sessionId, lastSeq, items: [动作, …] } }
```

### 4.2 确认已消费

```
POST /companion/ops/control/ack
body: { "session": "<会话id>", "ids": ["act_12_ab3f", …] }
→ { ok: true, value: { acked: 1 } }
```

> `ack` 之前动作会一直留在队列里（最多 100 条），适合「皮套崩溃重启后接着取」。

### 4.3 动作形状

```json
{
  "id": "act_12_ab3f",
  "seq": 12,
  "sessionId": "session-…",
  "type": "expression",
  "payload": { "name": "爱心眼" },
  "ttlMs": 12000,
  "createdAt": "2026-11-13T08:00:00.000Z",
  "acked": false
}
```

| 字段 | 说明 |
|---|---|
| `type` | 自由字符串；内置约定见下表，未知 `type` 原样透传 |
| `payload` | 该动作的参数对象 |
| `ttlMs` | 建议存活时间（1000~600000，默认 15000）；消费方自己决定过期丢弃 |
| `seq` | 单调递增，配合 `after` 增量拉取 |

内置约定（`GET /companion/ops/spec` 里有机器可读版本）：

| type | payload | 含义 |
|---|---|---|
| `expression` | `{ "name": "爱心眼" }` | 切表情，到 `ttlMs` 自动收回 |
| `motion` | `{ "name": "举手" }` | 播一个动作 |
| `look` | `{ "x": 0~1, "y": 0~1 }` | 看向屏幕某处 |
| `say` | `{ "text": "…" }` | 让她说一句话（皮套可以只做口型） |
| `param` | `{ "id": "ParamAngleX", "value": 20 }` | 直接写 Live2D 参数 |
| `emote` | `{ "emotion": "开心", "intensity": 0~1 }` | 情绪化表达 |

### 4.4 其余接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/companion/ops/spec` | 接口说明 + 块清单 + 动作类型（给接入方自描述用） |
| GET | `/companion/ops/state?session=` | 当前配置 + 上次运行 + 语言习惯 + 待取动作 |
| POST | `/companion/ops/run` | 立即分析一次 `{"session":"…"}`（面板按钮就是用这个） |
| POST | `/companion/ops/config` | 改分配 `{"session":"…","patch":{…}}`（等价于 `/companion/api/performance` 带 `ops`） |

所有 `/companion/ops/*` 与 `/companion/api/*` 用同一套信任校验（回环/可信 Host/非跨站），本地调用不需要 token。

### 4.5 皮套接入示例（伪代码）

```js
let after = 0
setInterval(async () => {
  const res = await fetch(`http://127.0.0.1:<端口>/companion/ops/control/pending?session=${encodeURIComponent(sessionId)}&after=${after}`)
  const { value } = await res.json()
  after = value.lastSeq
  for (const action of value.items) {
    applyToOne(action)            // 切表情 / 播动作 / 写参数 / 做口型
    // 处理完再一起 ack
  }
  if (value.items.length > 0) {
    await fetch('http://127.0.0.1:<端口>/companion/ops/control/ack', {
      method: 'POST', headers: { 'content-type': 'application/json' },
      body: JSON.stringify({ session: sessionId, ids: value.items.map((item) => item.id) }),
    })
  }
}, 1500)
```

> 端口读 `<数据根>/api-endpoint.json` 的 `port`（DSH 端口会变，别写死）。

## 5. 触发时机与安全边界

- **主触发**：`agent/status → idle`（这一轮真的结束了才跑，最稳）。
- **次触发**：宿主事件 `agent/turn-stopping`（一轮确定要结束时，`serial` 事件），和 idle 互为保险，用签名去重不会跑两次。
- **兜底触发**：收到 `assistant/message` 后 2.5 秒，若 agent 已空闲再跑一次；多步工具回合中途**不会**跑，避免把动态上下文改掉导致宿主注水。
- 同一轮只跑一次：用「缓冲消息条数 + 最后一条时间」当签名去重。
- 单次运行超时 90 秒自动中止；`split` 模式某一块失败只记该块错误。
- QQ 路由会话（`qq-bridge` 认领的会话）：分析照常跑，但**不注入**语言习惯——沿用 `dynamic-context.js` 的 QQ 判断（宿主会把刷新后的上下文快照当成用户新消息）。
- 插件卸载/热重载时清掉缓冲与定时器；`ops.json` 里的语言习惯、动作队列保留。

## 6. 和旧机制的关系

| 旧机制 | 新机制 | 关系 |
|---|---|---|
| `turn_end`（主模型自觉调用） | `ops-agent` | 并存。`turn_end` 仍是最准的（主模型知道自己写了什么）；`ops-agent` 补「模型没调、但这一轮确实有东西」的缺口 |
| `passiveTurnEnd`（漏调时的兜底抽取） | `ops-agent` | 并存。passive 只在「没写」时触发一次小调用；ops 是每轮固定分析，且块更多 |
| 习惯小模型 `habit-hint` | ops 的 `memory` 块 | 互补：习惯模型学「用户习惯」（写「对话人习惯」），ops 的 memory 块记「值得长期记的剧情/约定」 |
| 睡眠期预计算 `/companion/api/sleep-compute` | ops 的 `control` 块 | 不同阶段：睡眠是空闲时预判；ops 是每轮实时产出可消费动作 |

## 7. 排查

1. 面板没出现新卡片：刷新页面（`client.js` 改动走 HMR，刷新即生效）。
2. 接口 404：宿主插件没重载，`plugin_manager` 对 `include:companion-memory` 关再开一次。
3. 一直不跑：看 `<数据根>/ops.log`；没日志就先确认「每轮都调用」开关、当前对话是否开了伴侣记忆。
4. 跑起来但没写回：看 `ops.json → lastRun.error`，多半是模型没按 JSON 输出（失败会被记下，不影响下一轮）。
