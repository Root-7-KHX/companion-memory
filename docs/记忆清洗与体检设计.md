# 记忆清洗与体检设计（草稿 · 目标版本 1.1.0）

> 用户口径：「上传记忆的时候，能不能先自动把记忆过一遍？」
> 目标：导入前用「规则 + 一次模型调用」把记忆整理干净；同一套管线复用成面板上的「记忆体检」。

## 1. 现状

`importBundle` 只做机械处理：

- 精确去重（`dedupeBy`，按 id 或完全相同的文本）；
- 聊天原文保护（最多 500 条、单条 6000 字）；
- 从聊天原文里抽最多 6 条「用户说过」的事实；
- 没有语义层面的合并/删减/排序。

## 2. 处理管线

```
导出包
  │
  ├─① 解析与校验（格式、版本）
  ├─② 规则清洗（本地，0 成本）
  │    · 完全重复 / 仅空白大小写差异 → 合并
  │    · 超长条目 → 截断（保留开头 + 结尾）
  │    · 超过 30 个交互日的次要记忆 → 归档，不进活跃记忆
  │    · 每类上限裁剪（活跃记忆 30 / 演化每类 12）
  ├─③ 模型清洗（一次调用，失败则跳过）
  │    · 合并同主题 / 近义 / 重复
  │    · 删除一次性闲聊、已作废、纯玩笑
  │    · 按重要度排序
  │    · 输出 keep / merge / drop（结构化 JSON）
  ├─④ 合并进当前状态（合并导入 / 覆盖导入）
  ├─⑤ 导入聊天原文（沿用现有保护）
  └─⑥ 回执 + 备份 + 归档留痕
```

## 3. 模型清洗的硬约束

1. **`important` 与 `pinned` 条目原样保留**：
   - 只允许「去重」（完全相同的只留一条）；
   - **不允许改写、概括、删除**。
2. 只清洗 **次要记忆**（`source: turn / import / 48h概括` 等）与本次导入带进来的条目；
   人格文档（docs）、好感度、羁绊、演化条目**不参与**。
3. 不得新增导出包里不存在的事实。
4. 输出必须可校验：

```json
{
  "keep":   [{ "id": "mem_x", "reason": "保留原因" }],
  "merge":  [{ "from": ["mem_a", "mem_b"], "text": "合并后的短句", "reason": "…" }],
  "drop":   [{ "id": "mem_c", "reason": "一次性闲聊" }]
}
```

- id 必须在输入集合里，越界/重复/缺字段 → 整次清洗判失败，按原样导入；
- 合并后的 `text` 沿用原有标签与来源，长度 ≤ 120 字。

## 4. 备份与可回溯

- 导入前把目标会话的 `state.json` 复制到 `backups/state-导入前-<时间>.json`；
- 被 `drop` / `merge` 掉的原文条目写入归档：
  `archive/<日期>-导入清洗.md`（带时间戳，可 `search_kb` 找回）；
- 面板「撤销本次导入清洗」用备份恢复（与撤销好感度分开记录）。

## 5. 回执与 UI

导入确认卡片：

```
将导入：文档 3 份 / 活跃记忆 42 条 / 聊天原文 117 条（约 9k 字）
☑ 导入前自动整理记忆（推荐，调用一次模型，约 8k tokens）
[合并导入]  [覆盖导入]
```

导入完成后回执：

```
已导入。记忆整理：保留 28 / 合并 9 组 / 丢弃 5 条（已归档可回溯），约省 6.2k 字符。
```

## 6. 记忆体检（复用同一管线）

- 面板「记忆 → 体检」按钮：
  - 扫描当前会话的活跃记忆、演化条目、知识库索引；
  - 输出问题列表：完全重复、高度相似、互相冲突（如「喜欢猫」vs「讨厌猫」）、超长、过期未归档；
- 「一键修复」= 对选中条目跑模型清洗（同上硬约束）；
- 结果可预览、可撤销（自动备份）。

## 7. 失败与降级

- 模型调用失败 / 超时 / 输出不可校验 → 跳过清洗，按原样导入（绝不阻塞导入）；
- 规则层永远先跑（免费且可预测）；
- 清洗只在「导入确认」时触发，不会在后台自动改已有记忆。

## 8. 成本

- 典型导入：活跃记忆 30~60 条（每条 ≤120 字）+ 摘要若干 ≈ 8k~15k tokens 输入；
- 输出结构化 JSON ≤ 2k tokens；
- 使用 deepseek-flash 一次调用，成本可忽略。

## 9. 与 1.1.0 其他模块的关系

- 共用请求模型的能力（`lib/context-compress.js` 的 `requestSummary` 封装，抽成 `lib/llm.js`）；
- 与「多级记忆压缩」共用 pinned 规则与备份机制；
- 与「记忆体检」共用清洗管线。

## 10. 测试计划

- 规则层：去重、截断、过期归档、上限裁剪；
- 模型层：非法 JSON / 越界 id / 缺字段 → 整体回退原样导入；
- 约束：`important` 与 pinned 条目零改写（对比导入前后原文逐字一致）；
- 回执数字与实际条数一致；
- 撤销：备份恢复后状态与导入前完全一致；
- 回归：不影响现有导入、导出、好感度、聊天原文导入。

## 11. 里程碑

- M1：规则层 + 备份/归档（1 天）
- M2：模型清洗 + JSON 校验 + 回退（1~2 天）
- M3：导入 UI 勾选 + 回执（1 天）
- M4：记忆体检复用管线 + 面板（2 天）
- M5：测试 + 文档 + 1.1.0 发布
