# companion-memory（AI记忆）项目思路总结

> 版本：**1.1.2（未发布，上一发布版为 v1.1.1）** ｜ 整理日期：2026-10-30
> 一句话：给 DeepSeek Harness 的聊天 Agent 加一层「长期陪伴记忆 + 关系量化」，
> 让角色记得住旧事、分得清人、知道自己和对方的关系走到了哪一步，同时不把上下文撑爆。

---

## 一、为什么做这个

普通聊天 Agent 的问题是「聊完就忘」：上下文一压缩，人设和关系全丢了；记忆一多，prompt 又被
流水账塞满。这个项目要解决四件事：

1. **记忆要分层**——最近的原文放在热缓存里可以直接引用；更早的内容进知识库（带时间戳、可检索）；
   长对话则压缩成「记忆块」，既不丢主线又不占上下文。
2. **人设要稳**——三份侧边栏文档（角色性格 / 允许&禁止行为 / 预设发言例句）永远优先；
   角色还能在长期相处里慢慢「自我演化」，但只能加细节、不能推翻核心设定。
3. **关系要量化**——好感度是粗粒度的喜恶；羁绊是满值之后还能继续累积的深度；
   再往下是「多维评价」（信任/亲近/尊重/依赖/警惕/吸引…），由 AI 自己打分、维度还能自己增删。
4. **一切都是可解释、可恢复的**——记忆原文永不改写；归档带「归档时间 + 原始记录时间」；
   有备份、有撤销、有导出导入；面板默认只显示要紧的，向量和权重藏在后台。

## 二、总体架构

```
index.js                    插件入口：apply() 里按顺序装配 8 个模块
├─ lib/manager.js           多对话管理器：每对话一个 CompanionStore，开关/可见性/注册表
├─ lib/prompt.js            系统提示词：静态规则 + 每轮动态状态
├─ lib/tool.js              companion_memory 工具（17 个 action，含 guard 拒绝未开启对话）
├─ lib/tracking.js          事件追踪：用户/助手消息 → 热缓存、交互日、常问统计、去重锚点
├─ lib/dynamic-context.js   每轮注入「本轮动态状态」（好感度/记忆/向量/维度…）
├─ lib/lean-tools.js        开启伴侣记忆的对话精简工具集（减少工具目录体积）
├─ lib/context-compress.js  上下文压缩：把最旧的一段对话压成伴侣记忆格式
├─ lib/hierarchy.js         多级记忆压缩：日→月→年报→跨年沉积
├─ lib/api.js               /companion/api/* HTTP 路由（面板用）
├─ lib/store.js             全部数据与规则（约 145 KB，项目最核心）
├─ lib/recent.js            最近两个聊天日的原文热缓存
├─ lib/clean.js             记忆清洗/体检（规则 + 模型排序归档）
├─ lib/llm-call.js          摘要/清洗时的小模型调用
├─ client.js                侧边栏面板（React 风格 h() 渲染，6 个页面）
└─ scripts/package-dist.mjs  打包脚本（供发布用；本地工作区用 build-dist.mjs）
```

**Host / Client 分离**：Host 只负责数据与规则，Client 只负责渲染，两者通过 `/companion/api/*`
通信。所以面板刷新、样式改动都不影响记忆逻辑；Host 侧代码改动需要重载插件（改
`cordis.patch.yml` 的 `disabled` 开关）才生效。

**多对话隔离**：插件实例只有一个，但数据按对话隔离：
`sessions/<sessionId>_<hash>/`。对话默认关闭，只在侧边栏「开启本对话」后才会注入提示词、
注册工具、追踪消息。

**全局文件**（所有对话共享）：
- `<数据根目录>/character.json`——AI 的名字默认值（用户可改，AI 不可改）；
- `<数据根目录>/vector-dimensions.json`——记忆向量的全局维度定义；
- `<数据根目录>/speaker-vector-dimensions.json`——说话人评价的全局维度定义。

## 三、记忆体系（本项目的核心）

### 3.1 三层记忆 + 两层检索

| 层 | 位置 | 特点 | 怎么用 |
| --- | --- | --- | --- |
| 热缓存 | `recent.json` | 最近 **2 个聊天日**的原文 | `search_recent` / `read_recent` 直接引原话 |
| 知识库 | `archive/` `monthly/` `packs/` `hierarchy/` | 带时间戳的归档、48h 归纳、自动打包、月度、上下文压缩记忆、多级摘要 | `search_kb` / `read_archive` |
| 上下文压缩 | 会话 surface | 最旧的一段被替换成「记忆块」 | 模型只看到摘要，原文仍存本地日志 |

「聊天时间」按聊天日计算：只有真正聊过天的自然日才推进（每天 24 小时），中断一周不消耗额度。

### 3.2 活跃记忆（重点原文）

- 保存时**原文一字不改**，AI 只有保存/检索/归档的决定权。
- 每条带：`id`、原文、标签、来源说话人、**记录时间**（`YYYY-MM-DD HH:MM`）、
  **权重 1~100**（排序/取舍）、**向量**（见 3.3）。
- 生命周期：满 **30 个交互日**自动移入知识库（原文不变）；也可以手动归档、删除、置顶、上下移动。
- 排序：置顶 → 权重 → 手动顺序；每轮只注入前 8 条（高权重优先）。
- 归档条目格式固定：

```
归档日期：2026-10-30 20:13｜类型：重点原文（手动归档）
原始记录时间：2026-10-30 19:05（第 1 交互日）
向量：情感+60｜重要90｜亲密50｜敏感20｜长期70｜偏好
原文：
（一字不改的原文）
```

### 3.3 记忆向量（AI 自己打分）

每条记忆带 5 个固定维度 + 类别 + 最多 3 个自定义方面：

| 维度 | 范围 | 含义 |
| --- | --- | --- |
| 情感 valence | -100~100 | 负=难过/雷区/坏回忆，正=开心/喜欢 |
| 重要 importance | 0~100 | 设定/底线 90+，重要事件 70~89，琐事 0~39 |
| 亲密 intimacy | 0~100 | 越私人越高 |
| 敏感 sensitivity | 0~100 | 踩雷风险 |
| 长期 persistence | 0~100 | 是否长期有效 |

- `category`：偏好 / 约定 / 事件 / 人物 / 雷区 / 日常 / 其他。
- `aspects`：AI 自定义的「方面」（如 饮食80、工作50），最多 3 条。
- **全局维度**：AI 还能用 `vector_dimension` 新建「贯穿所有对话」的维度（最多 12 个），
  之后任何记忆都能用 `vector.custom` 按它打分。维度定义存全局文件。
- **删除保护**：有记忆还在用某个维度时不允许删除（活跃+已归档，跨对话统计），
  要先清掉分数；强制删除仅内部脚本可用。

### 3.4 提示词里长什么样

动态状态每条记忆渲染为：

```
· 【mem_936f50a7】2026-10-30 19:14｜情感+60｜重要90｜亲密50｜敏感20｜长期70｜偏好｜饮食90｜原文（权重 80）
```

面板默认把它收起来（「显示向量/权重」开关），只在后台生效——用户不想被长串数字刷屏。

## 四、关系体系（人和人之间）

### 4.1 好感度

- 对象是【角色对当前说话人】，-100~100，多人对话里每人一套、分开计算。
- 每次评估必须写理由；不聊天不会自动衰减；面板可手动拖动（手动改动不走羁绊缓冲）。
- 变动会归档，并且可以从面板「撤销最近一次」。

### 4.2 羁绊值（无上限）

好感度到 ±100 封顶，但关系还能更深，溢出部分记进羁绊；反过来降好感度时：

> **① 先扣羁绊 → ② 羁绊扣光后扣好感度 → ③ 好感度到 -100 后继续扣羁绊（转负）**

- 满值同向推动（还是在说「还是这么喜欢」）会记羁绊 +1，不会白记。
- 回执会如实说明「先扣羁绊 X、好感度实际只降了 Y」。

### 4.3 每个人的多维评价（1.1.2 新增）

- 默认 6 个维度：**信任 / 亲近 / 尊重 / 依赖 / 警惕 / 吸引**（0~100）。
- AI 用 `speaker_vector` 更新（只改传进来的维度；`null` 表示清掉）；
  `turn_end` 里也能直接带 `speakerVector`。
- 维度是**全局可管理**的：`speaker_dimension` 新建/删除（最多 12 个），
  有说话人用过的不许删。
- 存储是稀疏的：只存显式打过的分，展示时补默认值，所以「建了维度但没人用」不会占满。

### 4.4 一次事故教我们的（已写进防错）

AI 曾把「好感度目标值」传成 3（实际是「+3」的意思），从 100 掉到 3 = 掉 97 点，
被羁绊全部吸收，面板只显示「100（0）｜羁绊 143 → 46」，看起来像「明明是好事却扣羁绊」。

修复：历史记录保留 AI 的原始请求值 `requested`，面板/提示词显示「目标值 3｜羁绊抵消 97」，
回执明确提示 **value 是绝对值不是增量**，静态规则里也加了警告。

## 五、提示词是怎么组装的

1. **静态段**（每轮重建，但内容稳定）：AI 名字 → 三份文档 → 记忆规则 → 好感度/羁绊规则 →
   说话人识别 → 多维评价规则 → 自我演化规则 → 知识库规则 → 工具协议 + 硬性约束。
2. **动态段**（每轮刷新）：当前说话人/好感度/最近变动 → 每个人的多维评价 → 活跃记忆（≤8 条，
   带时间/向量/权重）→ 自定义维度 → 自我演化条目 → 交互日与周期 → 热缓存状态。
3. **记忆工具协议**要求模型每轮回复前调用一次 `turn_end`（重要原文、次要摘要、好感度/羁绊、
   多维评价一次写清），并用「本轮已记录」去重，避免模型重复调用浪费上下文。

## 六、companion_memory 工具（17 个动作）

| 动作 | 作用 |
| --- | --- |
| `turn_end` | 每轮一次：重要原文 + 次要摘要 + 好感度/羁绊/多维评价 |
| `save_important` | 单独保存重要原文（可带权重/向量/类别） |
| `set_favorability` | 好感度（自动处理满值溢出与羁绊缓冲） |
| `bond` | 单独增减羁绊 |
| `speaker` | 登记/切换说话人 |
| `speaker_vector` | 更新某个人的多维评价 |
| `speaker_dimension` | 增删说话人评价维度（全局） |
| `edit_doc` | 小步修改角色性格/例句（rules 默认禁止；必须写理由） |
| `vector` | 给已有记忆重新打向量分 |
| `vector_dimension` | 增删记忆向量维度（全局） |
| `search_recent` / `read_recent` | 最近两个聊天日的原话 |
| `search_kb` / `read_archive` | 知识库检索/读原文 |
| `archive_memory` | 手动把记忆移入知识库 |
| `summary48h` | 提交 48 小时归纳 |
| `evolve` | AI 自我演化（性格/喜好/讨厌/习惯，带权重） |

## 七、上下文管理与知识库

- **48 小时归纳**：到期时提示模型先提交归纳，再正常对话。
- **自动打包**：每 N 轮（面板可设）把区间内的重点/摘要/好感度变更打包成 `packs/自动打包_*.md`。
- **月度归档**：每 30 个交互日生成周期汇总 `monthly/对话月度归档_*.md`。
- **上下文压缩**：超过阈值（默认 50% 窗口）时把最旧的一段压成「记忆块」写进
  `packs/上下文压缩_第N次_*.md`，替换会话里的旧区间；失败安全放弃，溢出报错后强制压缩重试。
- **多级记忆压缩**：日→月→年报→跨年沉积，只保留两份高层摘要，原文永不删。
- **记忆清洗/体检**：规则去重 + 模型排序归档 + 超长/过期扫描；整理前自动备份 state.json。

---

## 八、侧边栏面板（6 页）

1. **配置**：三份文档逐字段编辑；AI 名字（全局默认 + 本对话覆盖）单独放在最顶上。
2. **记忆**：好感度/羁绊、活跃记忆、自我演化、手动保存、记忆体检；向量与权重默认隐藏，
   点「显示向量/权重」才展开。
3. **知识库**：按日期的归档、月度/自动打包/压缩记忆、关键词检索与原文查看。
4. **状态**：交互日、48h 到期、周期进度、在场人物、数据目录与统计。
5. **总览**：只读，把注入给 AI 的每一块内容原样列出，方便核对。
6. **备份**：整套数据导出为 JSON（可选择是否带聊天原文），导入可选合并/覆盖。

## 九、工程与质量

- **测试**：4 个 Node 脚本共 **302 项**断言
  （part1 存储/提示词 136、part2 工具+HTTP API 88、part3 检索/导入导出/压缩/清洗 61、part4 装配与事件 17）。
- **防错兜底**：turn_end 去重锚点、重复调用只补写、工具 guard 拒绝未开启对话、
  压缩失败降级、导入失败可回退、面板改动前备份。
- **版本策略**：没发布出去的改动全部并回当前版本号（现在是 **1.1.2**），发布后才 +1。
- **打包**：`build-dist.mjs` 生成可直接部署的 zip（含 BOM 清理、文件白名单、SHA-256 校验）。

## 十、当前状态与后续

**已完成**：记忆（权重/时间/向量/全局维度）、关系（好感度/羁绊/多维评价）、知识库与两级检索、
48h/自动打包/月度/多级压缩、上下文压缩、清洗体检、导入导出、面板 6 页、302 项测试。

**已知限制 / 可继续做**：
- 记忆向量目前是「AI 自评的多维刻度」，不是 embedding 语义向量；做语义检索需要再接向量库。
- 群聊是「同一对话多人轮流说话」形态，真正的群聊接入还没做。
- 面板还不能手动增删全局维度（只能 AI 建或脚本改），可以补按钮。
