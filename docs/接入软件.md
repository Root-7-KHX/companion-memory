# 接入软件

> 面板里「接入软件」这一页怎么用，以及怎么让别人（或者你自己）把一个软件真正接进来。

## 这一页是干什么的

把「能和 AI记忆 配合的外部软件 / 通道」集中列出来：QQ 机器人、其他聊天通道、消息桥、导出工具……
页面上有：

- 右上角一行小字 **申请收录软件 ↗**：和插件市场一样，点了直接去 GitHub 提交收录申请
  （仓库里的 Issue 模板 `integration_submission.md`）。
- 一个**搜索框**：按名称、说明、作者、分类、标签、能力搜；空格分隔多个关键词 = 必须同时命中。
- **卡片列表**：每个软件一张卡，显示名称、版本、分类、标签、说明、作者、主页链接。
- **「怎么把一个软件接进来？」**：折起来的一段说明，展开有步骤和示例清单。

## 一、只登记（零代码，谁都能做）

软件本身不用改任何东西，只要放一份**清单 JSON**：

1. 打开数据目录下的 `integrations` 文件夹（面板里「这里还空着」那段会显示完整路径，
   默认是 `<DSH_HOME>/companion-memory/integrations`，一般是 `C:\Users\你的用户名\.dsh\companion-memory\integrations`）。
2. 新建一个 `<id>.json`，也可以先在页面点「生成示例清单」拿 `example.json` 照着改。
3. 回面板点「刷新」，卡片就出现在列表里。

字段（只有 `id` 和 `name` 是必须的，其余写了更好搜）：

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一标识，建议英文短名（文件名兜底） |
| `name` | 显示名称 |
| `description` | 一句话说明它能干什么（也可写 `desc`） |
| `version` | 版本号 |
| `author` | 作者 / 维护者 |
| `category` | 分类，例如 通道 / 工具 / 记忆 |
| `tags` | 字符串数组，方便搜索 |
| `capabilities` | 字符串数组，例如 `["读消息", "发消息"]` |
| `homepage` | 主页链接（只认 http/https） |
| `entry` | 预留：以后版本用来自动加载桥接脚本，**这一版不会执行** |

示例（和面板里「生成示例清单」生成的那份一致）：

```json
{
  "id": "example-software",
  "name": "示例软件",
  "description": "把这份 JSON 改成你要接入的软件：说清它是什么、能干什么。",
  "version": "0.1.0",
  "author": "你的名字",
  "category": "通道",
  "tags": ["示例", "改我"],
  "capabilities": ["读消息", "发消息"],
  "homepage": "https://github.com/your-name/your-integration"
}
```

> 清单只是一份**描述**，插件不会执行里面的任何代码；一份 JSON 写坏了只会被跳过，不影响其它条目。

## 二、桥接（软件把内容写进 AI记忆）

想让 QQ 消息、邮件、日程这些东西真的进入某个对话的记忆，做法是让那个软件调本插件的本地接口
（同源 / 回环请求，和面板用的是同一套，默认只接受 loopback 或受信任的宿主来源）：

```http
POST /companion/api/memory/add
content-type: application/json

{
  "session": "<目标对话的 sessionId>",
  "text": "原话或重要信息，会原样进活跃记忆",
  "tags": ["来源:QQ", "群聊"]
}
```

其它常用的写入点：

| 路由 | 用途 |
| --- | --- |
| `POST /companion/api/memory/add` | 加一条活跃记忆 |
| `POST /companion/api/emotion` | 更新情绪表 |
| `POST /companion/api/speaker` | 登记/切换说话人（多人场景） |
| `POST /companion/api/doc` | 写人格文档字段 |
| `GET /companion/api/state` | 读当前对话的整体状态 |
| `POST /companion/api/session/say` | 往指定对话里发一条用户消息 |

要点：

- 所有写入接口都要带 `session`（query 参数或 JSON body），并且要**先在那个对话里开启记忆**，否则会返回「本对话未开启伴侣记忆」。
- 桥接进程如果是别的程序（例如 QQ 插件），照旧走 localhost 就行；跨机器访问默认会被同源校验挡掉。
- 数据仍然只落在`<DSH_HOME>/companion-memory/sessions/<对话>/`，不会外发。

## 三、做成 DSH 插件（长期方案）

如果那个软件本来就在 DSH 里跑（比如 QQ 插件），最稳的是**它自己做一个 DSH 插件 / 扩展**，
在进程内直接调本插件暴露的能力，而不是在「接入软件」页面里执行代码：

- 监听消息事件 → 调 `/companion/api/memory/add` 之类接口把内容写进记忆；
- 需要面板里的可视化，就照这份仓库的 `client.js` 写一个 `conversation.view` 或侧边栏面板；
- 需要区分群友，就先用 `/companion/api/speaker` 登记说话人，再记记忆和好感度。

这样：「接入软件」页面 = **目录与说明**，真正的桥接 = **各自插件自己的事**。
插件这边永远不执行别人的代码，安全边界清楚。

## 常见问题

- **放好清单了还是空？** 点「刷新」；如果提示「清单接口还没生效」，说明插件的宿主侧还没重载——重载一次 AI记忆 插件或重启 DSH 即可。
- **坏 JSON 会让整页挂掉吗？** 不会。单份坏清单只跳过它自己。
- **能重复吗？** 同一个 `id` 的多份清单都会显示；建议一个软件一份。
- **能删除吗？** 直接删掉 `integrations` 里的那个 JSON，再点刷新。
