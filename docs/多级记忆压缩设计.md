# 多级记忆压缩设计（草稿 · 目标版本 1.1.0）

> 一句话：把「日 → 月 → 最新年报 → 跨年沉积」做成级联摘要树。越老越浓缩，允许糊；
> 但**关键记忆（pin）永远原样保留**，原文永不删除、可随时下钻回溯。

## 1. 背景

现状只有两级：

```
L0 原文        最近 2 个聊天日（recent.json，可 search_recent / read_recent）
L1 日归档      archive/<日期>.md（追加式，带时间戳）
L2 摘要        月度打包（每 30 个交互日）+ 自动打包 packs/ + 上下文压缩 packs/
```

L2 之后不再收敛：月度包越攒越多，检索平铺，旧内容在检索时要扫很多文件。
用户明确接受「不重要的可以糊」，只要重要的记得住——所以做**有损但有保真的级联压缩**。

## 2. 目标与非目标

目标：
- 旧事低成本可检索：先看「跨年沉积 + 最新年报」，再下钻月报/日归档；
- 系统里长期只保留**两份**高层摘要：`epoch-累积.md`（所有更老年度）+ `annual-最新.md`（当前年度）；
- 关键记忆零损失：`important`、48h 归纳的 highlights、用户 pin 的「特殊记忆」在每一层原样搬运；
- 一年只跑一两次模型调用，成本可忽略。

非目标：
- 不做无损压缩（接受细节变糊）；
- 不删除任何原文文件；
- **不为每一年单独留一份年报文件**（只保留最新年报 + 累积沉积）；
- 不做跨会话合并（每个会话的伴侣记忆独立）。

## 3. 时间口径

- **周期** = 30 个交互日（聊天日）；
- **年度** = 12 个周期 = 360 个交互日；
- 全部按**聊天时间**累积：没聊天的日子不推进；
- 所以「年度」是第 1 年度、第 2 年度……的顺序编号，不对应自然年。

## 4. 层级定义

| 层 | 产物 | 目录 | 来源 | 触发 |
|---|---|---|---|---|
| L0 | 原文 | `recent.json` + DSH 会话日志 | 对话 | 实时 |
| L1 | 日归档 | `archive/<日期>.md` | 每轮记录 | 实时 |
| L2 | 月度摘要 | `monthly/对话月度归档_…md` | L1 | 30 个交互日（已有） |
| **L3** | **最新年报（只此一份）** | `hierarchy/annual-最新.md` | 最近一个已关闭年度的 12 份月报 | 新年度关闭时生成/替换 |
| **L4** | **跨年沉积（只此一份，滚动）** | `hierarchy/epoch-累积.md` | 上一版 epoch + 被替换下来的那份年报 | 新年度关闭时自动合并；或手动 |

层级目录（只有两类当前摘要，不按年份铺文件）：

```
hierarchy/
  index.json                    # 元数据（层级/覆盖范围/来源/压缩次数/时间）
  annual-最新.md                # 当前最新年度（第 N 年度），只压过一轮，最清楚
  epoch-累积.md                 # 覆盖第 1 ~ N-1 年度，被反复压缩过
  backups/
    epoch-累积.bak-第N次.md     # 每次合并前的备份（回滚用，不参与检索）
    annual-第N-1年度.bak.md     # 被并入沉积的旧年报备份（不参与检索）
```

`index.json`：

```json
{
  "annual": {
    "id": "annual-第3年度",
    "level": 3,
    "covers": { "fromAnnual": 3, "toAnnual": 3, "chatDays": 360 },
    "sources": ["monthly/…第25周期…", "…"],
    "sourceDigest": "sha256:…",
    "compressedTimes": 1,
    "createdAt": "2027-03-01T03:00:00+08:00",
    "file": "hierarchy/annual-最新.md"
  },
  "epoch": {
    "id": "epoch-累积",
    "level": 4,
    "covers": { "fromAnnual": 1, "toAnnual": 2 },
    "compressions": 3,
    "sourceDigest": "sha256:…",
    "createdAt": "2027-03-01T03:01:10+08:00",
    "file": "hierarchy/epoch-累积.md"
  }
}
```

## 5. 滚动规则（核心）

越老的记忆被压得越多；**只有最新一年是「一轮压缩、最清楚」**。

状态机（年度按关闭顺序编号 Y1、Y2、Y3…）：

```
Y1 关闭： annual-最新 = annual(Y1)                      ← 只有年报
Y2 关闭： epoch-累积 = 压( annual(Y1) )                ← 覆盖 Y1
          annual-最新 = annual(Y2)                     ← 只压过一轮
          （annual(Y1) 并入沉积，删当前文件、留 .bak）
Y3 关闭： epoch-累积 = 压( 旧epoch + annual(Y2) )      ← 覆盖 Y1~Y2
          annual-最新 = annual(Y3)
Y4 关闭： epoch-累积 = 压( 旧epoch + annual(Y3) )      ← 覆盖 Y1~Y3
          annual-最新 = annual(Y4)
```

要点：
- **任何时候只有两份高层摘要**：`annual-最新.md` + `epoch-累积.md`；
- 最新年报永远不进沉积，保证最新一年最清楚；
- 每次合并 = 旧沉积（已压多次）+ 上一份年报 → 新沉积（二度、三度压缩）；
- 每次合并前备份旧沉积和旧年报到 `backups/`，可回滚；
- 不删除任何原文文件，也不按年份铺年报文件。

## 6. 关键记忆保护（硬约束）

1. 记忆条目增加 `pinned: boolean` 字段：
   - `important[]` 保存时默认 `pinned: true`；
   - `summary48h` 的 highlights 进活跃记忆时默认 `pinned: true`；
   - 面板里用户可以手动 pin/unpin。
2. 级联摘要的输入里，**单独一块「关键记忆（原样，不许改写）」**，压缩提示词要求：
   - 不改写、不概括这一块，只允许去重；
   - 若与摘要正文冲突，以原文为准；
   - 不新增原文里没有的事实。
3. 每层摘要固定包含以下保真清单（有则写、无则略）：
   - 人名 / 关系 / 称呼变化
   - 关键约定、承诺、特殊日期
   - 特殊事件（第一次、纪念、冲突与和好）
   - 用户的固定偏好与雷区
   - 长期伏笔与未完成的事
4. pinned 原文不参与归档淘汰，也不参与任何概括，每层原样搬运。

## 7. 级联流程（以跨年沉积为例）

```
1. 确认刚关闭了一个年度 Yn（12 个周期完成）
2. 输入 = 当前 epoch 正文（若有） + 旧 annual-最新 正文 + pinned 关键记忆清单
3. 模型输出 ≤ epochSummaryMaxTokens 的结构化摘要
   - 失败 → 冷却重试，最多 2 次；仍失败则跳过，等下次触发
4. 备份旧 epoch 与旧年报 → 写新 epoch-累积.md → 写新 annual-最新.md
5. 更新 index.json（覆盖范围、compressions+1、来源 hash）
6. appendArchive('hierarchy', ...) 留痕
```

年度年报流程相同，只是源换成该年度的 12 份月报。

## 8. 触发规则

- 年报：该年度 12 份月报齐全时自动生成；也可手动「压缩到年度」；
- 跨年沉积：每关闭一个新年度时自动执行（Y2 关闭开始）；也可手动「跨年沉积」；
- 全部按**聊天时间**判断（没聊天的日子不推进），与现有 48h / 月度口径一致；
- 幂等：同一覆盖范围只生成一次；源 hash 变化才允许重做。

## 9. 检索策略（省 token）

`search_kb` 分级：

1. 先查 `epoch-累积` + `annual-最新` 两份高层摘要；
2. 命中后返回摘要片段 + 来源指针（可 `read_archive` 下钻到月报/日归档）；
3. 未命中再下钻 L2 月度摘要；
4. 最后 L1 日归档；
5. 返回结果标注层级和覆盖范围，AI 自己决定要不要继续下钻。

## 10. UI（面板「记忆 → 知识库」页）

- 层级树：L4 跨年沉积 → L3 最新年报 → L2 月报 → L1 日归档；
- 每层显示：覆盖范围、生成时间、压缩次数、约 tokens；
- 操作：手动触发压缩、查看/编辑摘要（只改摘要不改原文）、回滚备份；
- 记忆条目加 pin 开关（标记「特殊记忆」）。

## 11. 配置项

```yaml
- id: companion-memory
  config:
    hierarchy:
      enabled: true
      annualCycles: 12          # 12 个周期 = 年度
      yearSummaryMaxTokens: 3000
      epochSummaryMaxTokens: 2000
      auto: true
      cooldownMs: 600000
```

## 12. 错误处理

- 模型失败：记录日志，冷却后重试；连续失败则跳过本轮，不影响对话；
- 源文件缺失/被删：跳过该项并在 index 里记 warning；
- 并发：加会话级锁，避免重复生成；
- 摘要超长：截断并重试一次，仍超长则接受截断（记录）；
- 摘要过短/为空：判为失败，不写文件；
- 回滚：用 backups/ 里的文件恢复，index 记录回滚时间。

## 13. 成本估算

- 年报：读 12 份月报（每份约 2~4k 字符）≈ 40k 字符 ≈ 30k tokens 输入，输出 ≤ 3k tokens；
- 跨年沉积：读旧沉积 + 旧年报 ≈ 6k tokens，输出 ≤ 2k tokens；
- 每个年度总计两次调用，日常零开销。

## 14. 测试计划

- 单元：滚动状态机（Y1/Y2/Y3 关闭后的两份摘要）、幂等、pin 原样保留、index 读写；
- 集成：造 12 个月报 → 生成年报 → 校验摘要含 pin 原文、来源完整、原文未删；
- 跨年：Y2 关闭 → epoch=压(annual1)、annual-最新=annual2；Y3 关闭 → epoch=压(旧epoch + annual2)，校验覆盖范围与压缩次数；
- 检索：search_kb 层级优先级与下钻行为；
- 回归：不影响现有 48h 归纳、月度打包、上下文压缩；
- 会话日志兼容：本功能只写知识库目录，**不碰 session 日志**（避免再出现 0.7.0 那种 surface 改写导致会话损坏的问题）。

## 15. 里程碑

- M1：数据结构 + pinned 字段 + hierarchy 索引（1~2 天）
- M2：年度年报生成 + 手动触发 + API（2 天）
- M3：滚动跨年沉积（2 天）
- M4：分层检索 + 面板层级树（2 天）
- M5：测试 + 文档 + 1.1.0 发布
