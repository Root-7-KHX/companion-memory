# 群成员识别（QQ 桥接）

> 2026-10-31 新增。起因：要接 QQ 机器人的群聊，但「谁在说话」不能只看昵称——QQ 里改名是常态。

## 一、先看 QQ 机器人（dsh-qqbot）怎么做

它没有做「人物档案」，只做了一份**发言台账**（`dist/features/chat-ledger.js`）：

- 群成员台账：`{数据根}/表情包/group-members.jsonl`，每行 `{ts, gid, mid, name}`；
- `mid` = 群消息的 **member_openid**（稳定 ID），`name` = senderName（随时可改的昵称）；
- 只记**在群里发过言**的人（官方「成员列表」接口未开放，只能本地兜底）；
- 读的时候按 `gid + mid` 聚合，**每个成员只保留最新昵称**（append-only 文件每 200 条压缩一次）。

它踩过、也解决过的两个要点：

1. **私聊 openid 与群 member_openid 一致**（同一个机器人实例内）：所以私聊昵称缺失时，
   可以拿私聊的 `user_openid` 反查群成员台账，补出昵称（`dist/features/c2c-name.js`）。
2. `<@openid>` 这种正文里的 @ 标记，会拿台账换成 `@昵称`（查不到退 `@` + id 前 6 位），
   既省 token 又让人看懂 @ 的是谁（`resolveMentionNames`）。

### 它不够好的地方

- **只留最新昵称**：一改名，旧名字就丢了；记忆里同一个人出现两个名字时无法对上。
- 没有「改名事件」，也没法回答「这个人以前叫什么」。
- 台账按群分开，认人靠 `gid + mid`，跨群/私聊时要另外拼。
- 昵称重复的人（两个都叫「小明」）在纯昵称匹配下会串。
- 私聊昵称只能反查群台账：没在群里说过话的人，昵称仍然是 openid（这是数据缺失，不是 bug）。

## 二、AI记忆 这边怎么补

保留它的优点（**稳定 ID 为主键**），补上它没有的三件事：昵称历史、改名记录、跨对话认人。

### 1. 全局人物档案 `{数据根}/people/<platform>-<id>.json`

```json
{
  "version": 1,
  "platform": "qq",
  "instance": "1906147757",
  "externalId": "E9020753...",
  "currentName": "大明",
  "names": [{ "name": "小明", "firstAt": "...", "lastAt": "..." }],
  "renames": [{ "from": "小明", "to": "大明", "at": "..." }],
  "firstSeenAt": "...",
  "lastSeenAt": "...",
  "msgCount": 42
}
```

- 主键是 **platform + externalId（openid）**，昵称只当显示名；
- 改名时旧名进 `names`、`renames` 记一条，所以「他以前叫什么」查得到；
- 同名不同 openid = 两个人，不会混；
- 跨对话共享（认人是一辈子的，好感度仍然按对话隔离）。

### 2. 对话内的说话人：externalId 优先

`speakers` 里每个人多了 `externalId` / `platform` / `renameLog`：

- 解析顺序：**externalId → id/名字/别名**；
- 同一个人改名，只换显示名、旧名进 `aliases`、`renameLog` 记一条，**好感度/羁绊/多维评价/对话轮次全部保留**；
- 用 openid 直接引用说话人（`switchTo: "E9020753..."`）不会被当成改名。

### 3. 桥接怎么接（QQ 侧）

AI记忆 启动时会把本地接口地址写到 `{数据根}/api-endpoint.json`：

```json
{ "protocol": "http:", "host": "127.0.0.1", "port": 64603, "base": "http://127.0.0.1:64603/companion/api" }
```

QQ 扩展 `inbound/companion-speaker.mjs` 每条消息做一次：

```http
POST /companion/api/speaker
{ "session": "<这条 QQ 会话对应的 dsh 会话 id>",
  "platform": "qq", "externalId": "<openid>", "name": "<senderName>" }
```

- 返回里带 `renamed`（这次是否改名）与 `person`（档案摘要）；
- 接口不可用时（插件没开/端口没发布），扩展退回直接写会话 `state.json` 的老办法；
- 快照 `{QQ数据根}/companion-bridge/state.json` 每个说话人现在也带 `renames`，方便排查。

### 4. 好感度：只用 AI记忆 的

- QQ 机器人自带的 `attitude.json / affinity.json` 由启动钩子 `hooks/companion-bridge.mjs` **冻结成只读**（旁路），
  它写了也落不下去，读侧仍是旧值，不影响「主不主动开口」那套体验；
- 好感度、羁绊、多维评价全部走 AI记忆 的说话人记录（`speakers[].favorability/bond/vector`），
  按对话隔离、有历史、有理由、有羁绊抵扣。

## 五、接口速查

| 方法 / 路径 | 用途 |
| --- | --- |
| `POST /companion/api/speaker` | 登记/切换说话人；带 `externalId` 时同时更新全局人物档案 |
| `GET /companion/api/people?q=` | 列出人物档案（当前昵称/历史昵称/openid 模糊搜索） |
| `GET /companion/api/state` | 会话快照（`speakers` 里带 `externalId` / `renameLog`） |

## 六、还没做的

- 面板上还没有「人物档案」页（下次补：改名历史、跨对话出现过的群、消息数）；
- QQ 机器人自己的群成员台账（`group-members.jsonl`）还没合并进来当昵称兜底；
- 多个机器人实例（不同 AppID）的 openid 不互通，档案里用 `instance` 区分，暂不跨实例合并。
